Three complete opinions on the same work is what makes it a cross-check; splitting the dimensions is distribution, not verification. The script then **compares the firms**: `scoreAgreement` (same score = trustworthy · differ ≥2 = someone missed something, find out who) · `dimensionComparison` (per-dimension disagreement = open the code yourself) · `thoroughness` (catches a firm with no TRACE / no siblings / <10 dimensions scored — its result carries less weight) · `conflicts` (one filed what another cleared) · `corroborated`/`solo` · `intentAgreement`. **The prompt teaches the entire standard in full — all 28 sub-steps, all 10 dimension checklists, red flags, don't-flag rules, gates, scales, techniques — not a summary.** **❌ No auto-fix** (unlike Tester/supertester) — present findings + fix plan + blast radius, then ask. These two documents are also the yardstick #5/#12/#23/#24 are measured against. Hard rules: **score = LOWEST dimension, never the average** · **no concrete failure scenario ⇒ not a finding** · prove via 5 gates incl. **"am I reading the right instance?"** · always report the **no-action** list + the **not-covered** list; an **undeclared scope cut is a defect in the review itself**.

- **clean (#27, 2026-08-27):** trigger-only **refactoring / clean-code / formatting+speed** review of **ONE layer**, run through **`clean.js` (Workflow tool)**, args `{ workdir, layer, backup, branch, baseline }`. Defining sentence: **clean = change the SHAPE, never the BEHAVIOUR** — every proposal must carry a `behaviourProof` (how you'd prove the outside doesn't move) and **the script silently drops any proposal that leaves it empty**. **Exactly 3 firms, all three walking all three aspects themselves** (① structure ② clarity ③ format+speed) — ❌ they do not split the aspects, because "this reads better" is taste and refactor proposals need *more* cross-confirmation than bug hunts. Tiers: `DO` (3 firms) · `ADJUDICATE` (2 — Coddy opens the code and decides) · `LOG ONLY` (1 — possibly taste, never shipped as a to-do). **❌ Report-only: agents are read-only and Coddy must NOT flow on into fixing** — `clean` touches code that is *working fine*, the riskiest thing any trigger does (unlike Tester #5, which chases something already broken). **Four gates live in `clean.js` itself** and it refuses to open a single agent without all four: `layer` (one layer, never a repo — can't write the layer's outside edge ⇒ can't prove behaviour held) · `backup` (zip under `Backups/`) · `branch` (`clean/…`, never `main`) · `baseline` (test suite run **before** anything is touched; already red = no baseline = stop). **A bug found during `clean` is filed separately, never bundled** into a behaviour-preserving diff.
