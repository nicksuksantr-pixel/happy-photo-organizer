# SHARED_LESSONS.md — Cross-project bugs & lessons (shared by Cos + Coddy)

**The central registry of IMPORTANT, GENERAL bugs + their fixes across ALL projects.**
Reading MASTER surfaces this → any instance knows "who hit what important bug, and how it was
fixed" before starting work, so the same mistake isn't repeated in another project.

> Detail lives in each project's own `bug/` + `memory/MEMORY.md`. This file is the cross-project
> INDEX of the ones that bite OTHER projects too (curated; project-specific bugs stay in-project).
> A copy is mirrored into every project at `memory/SHARED_LESSONS.md` (via `sync-rules-to-projects.ps1`)
> so local AND cloud instances can read it. Format: **slug** (projects) — symptom → cause → fix.

- **Refresh:** periodically harvest each project's `bug/` + `MEMORY.md` (grep `Lesson`/`⚠`/`root cause`/`บทเรียน`) and promote the general ones.

## ⚙ Build / Release / Auto-update
- **gradle-loopback-windows-jdk21** (ScanDocs, Happy-Origin, MyDocs) — `flutter build` dies ~7s in: "Unable to establish loopback connection" (JDK21+Gradle9 on Windows). Cause: AF_UNIX pipe tmpdir bug + Gradle applies `-D` jvmargs AFTER daemon start, so `gradle.properties` is too late. Fix: set ENV `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/tmp -Djava.io.tmpdir=C:/tmp -Djava.net.preferIPv4Stack=true` + create `C:\tmp` (JVM honours it at startup).
- **build≠user-update** (HAPPY, PLC, OCR, Happy-Photo) — bumping/merging to main does NOT reach users; the updater pulls GitHub **Releases assets**. Release = build + push + `gh release create vX.Y.Z <asset> --latest` (+ SHA in body). `gh --target` needs a branch or FULL sha (short = 422).
- **updater-integrity-sha-gate** (HAPPY, PLC) — running a downloaded installer without a content-hash check = MITM/tamper risk. Parse expected SHA-256 from the release body, verify after download before launch; mismatch = wipe+retry; missing = skip (back-compat).
- **record-applied-only-after-success** (OCR) — writing "update applied" BEFORE the install runs poisons the updater forever on any failure. Gate solely on `is_newer(latest, RUNNING build)`; delete the poison flag on start.
- **version-compare-fixed-tuple** (OCR, HAPPY) — variable-length/zero-padded (`0.1.5.0`>`0.1.5`) or pre-release-equals-final compares break the updater. Fixed 3-tuple compare + pre-release < final.
- **check-update-every-start** (OCR) — a once-per-day throttle misses same-day releases. Check on every start (tiny anon call) + a manual "Check now".
- **play-versioncode-must-increase** (MyDocs, AI-Inventory) — Play rejects a duplicate versionCode; versionName may drop but versionCode must monotonically increase. Watch the **Gradle config-cache serving a stale versionCode** (just rebuild).
- **r8-for-native/sideload-apps** (Happy-Origin, AI-Inventory) — R8/minify fails on native/reflective deps (MediaPipe/protobuf); the failure is a **HARD CRASH**, not a silently-dead feature. For sideloaded apps disable R8 or add keep+dontwarn.
- **release-obfuscate-with-symbols** (AI-Inventory) — always `--obfuscate --split-debug-info=...\v<ver>` + ship symbols; a stale build note dropped them.
- **green-analyze/test≠release-build** (Happy-Origin) — analyze + unit tests run host-side and never exercise the Android release Gradle/R8 path. A real `build apk --release` is part of "done" for any native-plugin change.
- **pyinstaller-add-data-preserves-subfolders** (HAPPY) — `--add-data "src;."` flattens to bundle root → 404 on web assets. Use `dest = Path(asset).parent`.
- **pyinstaller-no-secret-in-spec** (HAPPY) — a PAT/.env bundled in the `.exe` is readable by anyone. Token-less updater (public repo) or a scoped/rotated PAT; never bundle secrets.
- **artifact-name-collision** (MyDocs, NotiWallet) — Flutter hardcodes `app-release.aab`; set `base.archivesName` + a `doLast` rename to `<App>-v<ver>.aab` and SHIP the renamed file (the build-log echo can be stale).
- **gh-release-notes-file** (OCR, MyDocs) — PowerShell here-strings mangle long inline `--notes`; Play caps notes at 500 chars/lang (fails at commit). Use `--notes-file`; keep ≤500/lang.

## 💾 Data / Persistence / Backup-Restore
- **atomic-write-everywhere** (ScanDocs, PLC, ENA) — in-place write of jobs.json/project/autosave → a kill or **power-loss** (Nick's ship dips) truncates and silently wipes. Write temp + flush + `os.fsync` + `os.replace` (atomic on NTFS).
- **parse-then-swap-never-clear-then-parse** (NotiWallet, ScanDocs) — restore that clears then parses a malformed/foreign backup wipes everything. Always parse-then-swap; extract to a staging dir then move; mirror the "claimed-but-none-parsed → abort" guard on EVERY box; only wipe when the zip has files; zip-slip guard.
- **wal-checkpoint-before-copy** (AI-Inventory, ENA) — copying a SQLite `.db` without flushing WAL gives stale data; leftover `-wal/-shm` on restore corrupts. `checkpoint()` before copy; delete siblings on restore. Wrap connections in `contextlib.closing` (a `with connect()` commits but never CLOSES).
- **new-field→update-(de)serialization** (NotiWallet, Happy-Origin) — adding a persisted field without updating to/from-map (or `fromMap` not reading a column) silently drops it on backup/reload. Update both maps in the SAME change + a round-trip test.
- **rebase-paths-inside-json-indexes** (ScanDocs) — restore that only re-bases prefs leaves absolute paths embedded INSIDE jobs.json → blank grid on a new device. Field-aware rebase of path fields ONLY (never password/credential fields), and only when the zip hasFiles.
- **open-box-retry-before-wipe** (NotiWallet) — auto-wipe on a single Hive `openBox` failure = data-loss time bomb. Retry 4x + restore from `.corrupt-*.bak`; check `apksigner` before blaming signing.
- **stream-large-zip-not-into-ram** (ScanDocs) — decoding a whole backup zip in RAM OOMs. Stream it.
- **soft-delete-upsert-reset-flag** (AI-Inventory) — upsert must set `deletedAt=null` on conflict, else it revives invisible trashed rows.
- **reset-static-caches-on-restore** (NotiWallet) — static caches mirroring the DB keep stale state after a restore. Reset them.
- **derive-identity-from-db-id-not-glob** (OCR) — numbering folders from a directory glob reuses a deleted id → "deleted jobs come back" + collisions. Derive identity from the monotonic DB id; make archive idempotent.
- **one-canonical-data-dir** (OCR) — splitting DATA_DIR on `sys.frozen` (dev vs installed) = two stores; many "wrong/old data" symptoms = ONE shared-state divergence first. One canonical `%LOCALAPPDATA%` store + migrate-legacy.
- **upsert-blank-cell-value-absent** (AI-Inventory) — `Value(blankCell)` = `Value(null)` overwrites existing columns on re-import. Emit `Value.absent()` for blanks.
- **audit-delta-from-live-not-snapshot** (AI-Inventory) — compute a stock delta from LIVE qty inside one txn, not a screen-open snapshot.
- **header-aware-table-mapping** (MyDocs) — mapping table cells by fixed positional index breaks when the real template's column count differs. Read the header row (handle gridSpan).
- **lexicographic-date-sort** (Happy-Photo) — sorting `DD-MM-YY` strings orders by day-of-month. Sort by a parsed `(yy,mm,dd)` key.
- **non-atomic-multi-connection-write** (OCR) — a merge across 3 DB connections loses data on a crash between steps. One transaction + a reconcile-on-start that re-folds any lost answer (idempotent).
- **empty-results-index-guard** (OCR, PLC) — indexing `results[0]`/`[-1]` or `max([])` crashes on empty input. Guard the empty case / pass `default=`.

## 🔐 Security / Secrets / Privacy
- **never-paste-a-real-credential-into-a-test** (Engine-Maintenance-Report) — a real Google API key was pasted into a test as a "format example" (to capture the shape of a key that a prefix check had wrongly rejected), then committed and pushed. The pre-push secret scan **printed the match** and it was waved through as "only a test file" — a scan you overrule is not a control. Credential fixtures must be SYNTHETIC (`"AQ." + "y"*43`). Once it is in history the only real remedy is **revoking the key**: rewriting history needs a force-push, which is forbidden here. Pairs with **no-client-side-format-check-on-a-credential** — needing the real key's shape at all was the mistake upstream.
- **verify-a-new-build-gate-by-building** (Engine-Maintenance-Report) — a payload check added to a PyInstaller build script required `_internal/google`, but PyInstaller compiles pure-Python packages into the **PYZ archive inside the .exe** and never creates a folder for them, so the gate always failed and no release could be cut. It was never executed after being added (gate 18:55, last build 18:16). Check data packages under `_internal/`, pure-Python ones by scanning `build/<name>/PYZ-00.toc`, add a pre-build import check — and **run the build once** after touching its gate. An unrun check is worse than none, because it looks like protection.
- **secret-never-in-tracked-file** (AI-Inventory, HAPPY) — a keystore password in MEMORY.md / a PAT shipped by auto-push. Reference secrets by LOCATION only; secret-scan staged CONTENT (`git grep --cached`) before the FIRST push.
- **unauthenticated-localhost-api** (OCR) — an on-by-default localhost POST API lets any local process spend quota. Require a token header (constant-time compare) on POST; GET-open is OK (CORS blocks browser reads).
- **android-allowbackup-false-for-secrets** (NotiWallet) — `allowBackup` defaults TRUE → financial DB/keys/PIN cloud-backed-up. Set `allowBackup=false` for any app holding secrets/financial data.
- **backup-doesnt-carry-credentials** (ScanDocs) — a backup zip carried users' plaintext PDF passwords; a blind path-replace also rewrote password fields. Warn+confirm before exporting; field-aware rebase never touches credential fields.
- **entitlement-not-backed-up** (ScanDocs) — never back up/restore `pro_active`; entitlement comes only from Play Billing.
- **strong-backup-kdf** (NotiWallet) — weak backup key-derivation. PBKDF2-HMAC-SHA256 (120k) + per-file salt.

## 🤖 AI / Gemini API
- **gemini-empty-candidates-rangeerror** (AI-Inventory) — `data['candidates']?[0]` throws RangeError on a SAFETY-blocked empty list (null-aware index only guards a null receiver). Empty-list-safe helper + throw a typed BlockedException (fail fast, no retry).
- **json-raw-decode-not-greedy-regex** (Happy-Photo) — greedy `{.*}`+DOTALL fails when the model emits prose/two objects. Use `JSONDecoder().raw_decode` scanning each `{`/`[`.
- **react-to-429-shared-cooldown** (NotiWallet, AI-Inventory) — a client limiter is per-device and can't cap a per-KEY quota across installs; proactive-only still 429s. REACT to the server 429 with a persisted SHARED cooldown; multi-device on one key needs separate keys; a 429 retry handler must CONSUME the budget or it loops forever.
- **grounding-separate-quota** (AI-Inventory) — Google-Search grounding has its own ~0 free-tier quota. On grounded-429 fall back to a plain call (static disable flag).
- **never-block-on-quota-in-timeout** (NotiWallet) — a quota-wait inside a timeout-wrapped path turns "quota exhausted" into "permanent failure". Bail fast with a retryable error.
- **tests-must-not-send-live-requests** (OCR, AI-Inventory) — smoke tests hitting the live sender burn real quota + drain the real queue; "green" hides it. Force the API key to None (returns before the drain) — NOT clear-rows (a queue-repopulating change defeats that guard); scope tests to rows they created + set a test DATA_DIR.
- **concurrent-drain-atomic-claim** (OCR, NotiWallet) — two drain paths grab the same item → double-spend quota. Module lock + atomic claim (`UPDATE…WHERE status='pending'`) + persist the dedup marker BEFORE the durable work; store content hashes, not file copies.
- **amount-in-text≠transaction** (NotiWallet) — a promo "win ฿999" got recorded as income. Promo gate (promo-signal AND no tx-signal) + an AI step-0 not_transaction check.
- **script-agnostic-on-device-gate** (NotiWallet) — ML Kit OCR is Latin-only, silently fails on Thai → everything floods the paid cloud. Use a script-agnostic signal (QR/2D barcode); fail CLOSED (skip) when OCR is unavailable.
- **thai-substring-intent-hijack** (NotiWallet, AI-Inventory) — Thai keyword matching by raw substring (Dart `\b` doesn't know Thai) mis-routes ('งบ' inside 'ยังไงบ้าง'). Thai-aware lookaheads + combine verb+noun signals.
- **resolve-provider-per-use** (AI-Inventory) — an agent capturing `ref.read(provider)` once keeps the stale keyless instance after a key change. Resolve per-use via a builder.
- **auth-gate-refresh-on-bg-validation** (HAPPY, AI-Inventory) — a key that passes format but is API-rejected (validated in background) must refresh the Run/insight gate.
- **verify-domain-data-vs-datasheet** (PLC) — a generated report embedded a fake part ('FX3N' = a clone) across versions. Verify model/domain names against a real datasheet, not AI/generated text; treat in-code warning comments as real signals.
- **tesseract-tha-on-english-hallucinates** (OCR) — `tha+eng` on no-Thai pages hallucinates Thai glyphs. Latin-dominance character-mass gate → rerun `eng` only; use `TESSDATA_PREFIX` env not a quoted `--tessdata-dir`.

## 🧠 Local / on-device LLM
- **thinking-model-shares-num_predict** (Open-Claw) — a thinking LLM returns ZERO answer (`done_reason: length`): think-trace + answer share one maxTokens budget. Raise the budget AND use an explicit `-instruct` tag (verify by manifest digest; bare/`-thinking` can't be disabled with `/no_think`).
- **local-llm-ram-paging-hang** (Open-Claw) — working set > free RAM → Windows pages to SSD → looks like a timeout (a bigger timeout never fixes a paging cause). Drop `num_ctx`; set `OLLAMA_KEEP_ALIVE` to free idle RAM. iGPU offload on shared DDR4 = ~0 gain.
- **on-device-llm-gated-download-dealbreaker** (Happy-Origin, Open-Claw) — a gated model + multi-GB download is the dealbreaker, not the code. For mobile, Ollama-direct beats a heavy agent prompt (CPU prefill overruns idle timeouts).

## 📱 Flutter / UI
- **imagefile-caches-by-path** (ScanDocs) — `Image.file`/`FileImage`/`imageCache` key by PATH not bytes; overwriting a fixed path shows the stale image. Unique filename + `ValueKey`, or evict the cache.
- **image-cachewidth-and-isolate** (ScanDocs) — full-res `Image.file` in a small cell OOMs / decoding on the main isolate freezes. Pass `cacheWidth`; move heavy image work to `Isolate.run` (pure-Dart only) in bounded batches.
- **riverpod3-keepalive** (ScanDocs) — Riverpod 3 auto-disposes by default → in-memory store dropped when the last watcher leaves. `ref.keepAlive()` in store providers.
- **runtime-theme-needs-watch-non-const** (ScanDocs) — a global-static token read won't notify + const widgets can't use runtime getters. `ref.watch` the theme on each page; drop `const` at broken sites.
- **predictive-back-bypasses-popscope** (NotiWallet) — Android target36 predictive-back bypasses PopScope. `enableOnBackInvokedCallback=false` + a BackPressHandler.
- **tree-shake-icons-runtime-codepoint** (MyDocs) — a runtime-built IconData is stripped by icon tree-shaking. Build with `--no-tree-shake-icons`.
- **dispose-controllers-and-ui-images** (AI-Inventory, ScanDocs) — TextEditingControllers in stateless dialogs + `dart:ui` Images + native `cv.Mat` leak. Dispose via `showDialog().then` / across the lifecycle; `try/finally` frees every Mat on the error path (guard `work==src` double-free).
- **stale-state-on-show/listen** (HAPPY, AI-Inventory) — `initState`-computed state in an always-mounted IndexedStack / segmented buttons / dropdowns goes stale after a Settings change. Re-sync from state on `on_show` / `ref.listen` in build (and `configure(values=)` when resetting a menu var).
- **pdf-page-physical-size** (ScanDocs) — raw image PIXELS used as PDF POINTS make an 80-inch page. Cap to a physical size (A4 842pt); embed the full-res image inside.
- **opaque-bg-per-transitioned-page** (ScanDocs) — translucent glass pages don't cover the old page on an instant push. Back each transitioned page with an opaque gradient (NOT BackdropFilter, which is expensive).
- **opencv_core-not-dartcv4** (ScanDocs) — `dartcv4` is the pure-Dart binding only (no Android `.so`) and dartcv4 2.2.1 uses native-assets hooks-1.0 that Flutter 3.44 (hooks-2.0) never invokes → green build, dlopen crash on first scan. Use `opencv_core` (bundles natives via gradle/jniLibs).
- **tk-shortcuts-die-on-thai-layout** (Engine-Maintenance-Report — hits EVERY Tk/CustomTkinter app Nick uses in Thai) — `Ctrl+C/V/X/A` silently stop working while the keyboard is on Thai: Tk binds them by **keysym**, and the Thai layout makes the V key report a Thai letter, so `<Control-v>` never matches. Worst exactly where it matters, since Thai text is typed with the layout on Thai. Fix: `bind_all("<Control-KeyPress>")` and dispatch on **keycode** (V=86, C=67, X=88, A=65) → `event_generate("<<Paste>>")`; return early when `event.keysym` IS the ascii letter, or an English layout pastes twice. Give any credential/URL field a **Paste button** as well — a button cannot be defeated by a layout.
- **no-client-side-format-check-on-a-credential** (Engine-Maintenance-Report) — a key field that demanded an `AIza` prefix REFUSED Nick's real, working Google key, which is issued as `AQ.…`; the app made it impossible to enter a valid credential, and the same file's docstring already said only the API can judge a key. Check only what cannot be a credential at all (too short / contains whitespace) and validate by **calling the API** with a Test button. Provider key formats change without notice.
- **ctk-geometry-multiplied-by-dpi** (Engine-Maintenance-Report — applies to every CustomTkinter app) — a hard-coded `geometry("1360x860")` renders ~1075 px tall on a 125% display: CustomTkinter multiplies the geometry string by the window scaling factor, so the bottom row (status line + primary button) hides under the taskbar, and on a 768-px laptop far more is lost. It reads as a layout quirk, not a sizing bug. Divide the wanted size by `ctk.ScalingTracker.get_window_scaling(window)`, clamp to the real screen minus a margin, and centre; keep `minsize` small enough for a ship laptop.
- **ctk-wraplength-scaled-twice** (Engine-Maintenance-Report) — a measured pixel width passed as `CTkLabel(wraplength=…)` clips the text instead of wrapping it: CTk multiplies the value by the widget scaling factor before handing it to Tk, so at 125% the wrap is asked 25% wider than the space that exists and the tail is cut ("check it befor"). It reads as a truncated string, not a scaling bug. Divide by `ctk.ScalingTracker.get_widget_scaling(widget)` first. Same family as **ctk-geometry-multiplied-by-dpi** — CTk scales *every* pixel value you hand it. Also: give a status label its own full-width row instead of sharing one with a button, or the message that matters is the thing squeezed.
- **ctkbutton-centres-wrapped-text** (Engine-Maintenance-Report) — `CTkButton(text=..., anchor="w")` still CENTRES the lines inside a multi-line label and then clips both ends, so list rows lost the start and end of longer names ("Replaced emergency alarm button…" → "laced emergency alarm button… (2 p"). `anchor` places the block, it does not justify the text. Build list rows from a frame + `CTkLabel(justify="left", wraplength=...)` and bind `<Button-1>`/`<Enter>`/`<Leave>`. Only shows up once a label is long enough to wrap, so short test data hides it.
- **shrink-to-fit-clamp-anchor-far-edge** (SHIP-MONITORING) — keeping an auto-width popup/tooltip inside a clipping parent by measure-width-then-set-`left` FAILS: the box re-expands into the freed space and eats the margin (3 fix rounds). On overflow anchor the OPPOSITE edge (`left:auto; right:8px`) for a stable width; reset the flip before re-placing. The clip boundary is the nearest `overflow:hidden` ANCESTOR, not the viewport — and verify UI geometry in a real browser vs the real CSS, not by code-reading.

## 🪟 Windows / Platform / tooling
- **release-manifest-internet-permission** (Happy-Origin) — flutter create adds INTERNET only to debug/profile manifests → release APK has no network. Add it to the MAIN AndroidManifest.
- **request-post-notifications-at-onboarding** (NotiWallet) — Android13+ notifications silently dead if POST_NOTIFICATIONS is behind a feature toggle. Request at first run.
- **powershell-bom-pipe** (Coddy) — piping a string into node/python adds a UTF-8 BOM → `JSON.parse` fails silently. Strip the BOM.
- **powershell-mangles-json-cli-arg** (Open-Claw) — PowerShell mangles a JSON arg to a native CLI. Write the JSON to the config file directly.
- **windows-python-print-cp1252** (Coddy) — `print()` of Thai to the console throws even after the file write succeeded. Keep tool stdout ASCII.
- **dpi-aware-screen-capture** (PLC) — capture of a frozen app crops on high-DPI. `SetProcessDpiAwarenessContext(-4)` before capture.
- **schtasks-change-needs-password** (ScanDocs) — `schtasks /Change` prompts for the account password. Overwrite the task's target `.bat` in place + `schtasks /Run` (stored creds).
- **git-longpaths-deep-pubcache** (ScanDocs) — a deep MSIX-virtualized pub-cache path exceeds the Windows limit. `git config --global core.longpaths true`.
- **grep-nul-false-negative** (Coddy) — ripgrep silently skips binary/NUL files; cross-check a "not found" with Read.
- **in-agent-flutter-build-cannot-work** (ScanDocs) — the in-agent shell can't run the full Gradle/Flutter build (sandbox/loopback). Build via a Windows Scheduled Task; only analyze/test/deploy run in-agent.
- **ps1-must-be-ascii** (SHIP-MONITORING) — non-ASCII in a `.ps1` (em-dash `—`, smart quotes, `→`, `·`) BREAKS the parser: Windows PowerShell reads a no-BOM file as the ANSI codepage, where the em-dash byte decodes to a smart double-quote (U+201D) that PS treats as a string delimiter -> cascading "missing }" / "unexpected token" errors far from the real spot. Keep PS source pure ASCII (or save UTF-8 *with* BOM); parse-check `[System.Management.Automation.Language.Parser]::ParseFile(...)` before trusting/shipping a script.
- **msix-shadow-hides-the-real-file** (SHIP-MONITORING, Coddy) — ⛔ **an agent shell launched from Claude desktop runs INSIDE its MSIX/AppContainer, so reads of `%LOCALAPPDATA%`/`%APPDATA%` are served from `…\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\…` whenever a copy exists there.** `$env:LOCALAPPDATA` still prints the normal path and no env var reveals the container. It is **copy-on-write**: files with no container copy read THROUGH to the real one — so a single directory listing mixes live files with months-old ghosts and every line looks plausible. Cost: two sessions independently concluded a ship's database "had not been written since 11 July" and burned hours on it; the real file was 129 MB written that same day, `write_ok=True`. **Decisive test (read-only): compare each file's mtime against the same relative path under `Packages\<app>\LocalCache\Local\` — identical mtime = you are reading the copy; no copy = the read passed through.** In our case that split 10/10 with no exception. Also check the parent chain (`powershell ← claude.exe ← …`). **The only measurement that escapes the box is the program reporting about ITSELF** (a startup log it writes) — not us measuring it from outside. Same family as `verify-before-delete-or-claiming-fixed` and the review standard's gate 2 ("am I reading the right instance?").
- **mdns-register-once-goes-stale** (SHIP-MONITORING) — a fixed-name zeroconf/mDNS service registered ONCE at launch goes dark when the box's IP changes / an interface bounces, while the raw-IP URL still works (multi-homed PC: phone saw "offline", server fine). The socket set is fixed at `Zeroconf()` CONSTRUCTION (no hot-plug). Fix = a watcher that re-announces on IP change with a FRESH instance per registration (close the old = goodbye); start it UNCONDITIONALLY (boot-before-WiFi must get its first registration late); ignore loopback/APIPA fallback readings; debounce a different-IP switch; back off on persistent failure; and any shown-URL side effect must fire INDEPENDENT of registration success.

## ⚙ Workflow / process / agents
- **agent-hard-cap** (NotiWallet) — fan-out "1 agent per finding" burned 24→60 agents. ≤3/round · max 5 · >5 STOP+ask. FAIL = stop+report, never blind-retry; a single transient (e.g. SSL timeout) on a real upload may get ONE retry AFTER diagnosing — only loop-retrying fleets is banned.
- **workflow-args-string-not-object** (tester/lucifer) — the Workflow harness passes `args` as a JSON STRING; `args.x` is undefined unless `JSON.parse`'d first.
- **edit-source-with-edit-tool-not-heredoc** (MyDocs, Engine-Maintenance-Report) — a bash heredoc turns `\n` into a real newline → SyntaxError. **Also: a PowerShell `(Get-Content x) -replace … | Set-Content x` round-trip CORRUPTS any non-ASCII in the file** — PS 5.1 reads UTF-8 as the ANSI codepage, so an em-dash comes back as `â€”` plus a BOM, and nothing reports an error (a one-character version bump silently mangled a docstring). Edit source only with Edit/Write; if a script must, `ast.parse` right after writing.
- **daemon-spawning-fn-needs-stop-for-tests** (SHIP-MONITORING) — a function that spawns a background daemon thread MUST take a `stop` event, and every test caller passes one + JOINS the thread by name (not sleep-and-hope). A stop-less test call leaked 2 immortal watchers that did REAL network work (advertised mDNS from pytest!), stalled later joins ~8s/suite, and could append into another test's monkeypatched fakes. Also: when a refactor makes a function spawn threads where it didn't before, grep EVERY existing test caller — the old "safe no-op" tests are now leaks.
- **a-guard-must-be-tested-with-the-bug-it-guards** (SHIP-MONITORING) — ⭐ **a guard written to stop a bug is worthless until the bug itself is used to make it fail.** In ONE day the same fail-open pattern got through three layers: the code (`getattr(s,"write_ok",True)`), the fix (the consumer re-created it as `.get("storageOk",True)` one layer later), and **the AST guard written to prevent it** — that guard understood `d.get(k, default)` but not `getattr(o, k, default)`, so it went green over the very line that started the whole thing. A second guard the same day passed while the startup wiring it existed to protect had been deleted, because the test called the function directly instead of driving the real path. **Both were caught only by reverting the fix and demanding red.** Rules: a new guard must be proven RED against the original defect before it is trusted; if it inspects source/AST, enumerate every syntactic form of the thing (`d.get` AND `getattr` AND attribute access); and if a test cannot exercise the real wiring, say so IN the test and assert the wiring structurally instead of pretending. **A guard that is green for the wrong reason is worse than no guard — it retires the worry.**
- **a-comment-is-not-evidence** (SHIP-MONITORING, Test-Memory) — ⭐ **a comment, docstring, release note or chat message that DESCRIBES code is not evidence about the code — only the line is.** One reviver round produced the same shape three times in a day, from three different people and three different artefacts: **(1)** `set_latched`'s docstring claimed it owned `on_since`, and a 9-line comment above it said the offending write had been removed "(the only BLOCKER of the round)" — a twin write sat **20 lines below in a sibling function**, so the BLOCKER the comment commemorated stayed open across a whole version, reachable through the button people actually press. **(2)** Reachability was read off the `@_gate(2)` decorator alone — the **decorator answers WHO, `REMOTE_METHODS` answers FROM WHERE** — and "cannot be fired from off the machine" reached a **published GitHub release note**, where it made readers under-rate how urgently to update. **(3)** The REVIEWER, in the very message correcting (2), stated which doc section held the bad sentence by lifting a "§8" out of an earlier chat message instead of opening the file — wrong section, asserted as fact, **inside a message whose entire content was "don't infer, open the line."** Fixes: before writing any claim about code — yours or someone else's — open it and cite `path:line`; when a comment and the code disagree the **comment is a bug too**, fix it in the same change; enumerate **every** writer/entry point of a shared field instead of trusting the one the comment names (`git grep` the field, not the function); and never treat the reviewer's seat as protection — **reading a story about code does this to anyone**, which is why the evidence gates apply to the review's own sentences, including the incidental ones about where something lives.
- **a-degraded-run-must-not-read-as-a-complete-one** (trigger scripts, 2026-08-27) — ⭐ **when a fan-out loses workers, the number you report must be the number that ANSWERED, not the number you launched.** All four review scripts returned `agentsUsed: LENSES.length` while `.filter(Boolean)` silently dropped dead agents, so a 1-of-3 audit read as 3-of-3 — and two of those scripts end in *fix → build → upload to Play*. Proven twice the same day: one run lost all three firms (quota) and one lost two (schema retry cap); the first would have reported a clean 3-firm review of a file **nobody opened**. Worse, the second-order version is subtler than the counter: after the count was fixed, the *derived* metrics still lied — `scoreAgreement` computed spread over the survivors and printed "all 3 firms agreed — highly trustworthy" **from a sample of one**, and lucifer's gate certified a Play upload on one surviving reviewer while carrying `deadReviewers` in the very object it returned. Rules: report `expected` and `actual` separately; make **every derived statistic branch on the survivor count**, not just the headline; the machine-readable `next`/instruction field must itself flip to STOP (a warning parked in a different field is not a control); and treat an empty result list as **"not examined"**, never "examined and clean". *Recording the degradation and then not consulting it is the trap — an honest flag sitting beside a fail-open number changes nothing.*
- **fix-the-sibling-set-not-the-file** (trigger scripts, SHIP-MONITORING, 2026-08-27) — ⭐ **a fix applied to 3 of 4 siblings is a new bug, and knowing that is not protection.** SHIP-MONITORING's BLOCKER was a write removed from `set_latched` and left in its twin twenty lines below; the audit that found it listed three more of the same shape. Then the fix-up for that audit **repeated it four times in one sitting** — the STOP path reached tester/supertester/security but not reviver itself, the Bash grant reached three scripts but not tester, the waiting-escape reached the full rulebook but not the brief every session actually reads, and a corrected phrase was fixed in the prompt but left in the round title that feeds the same prompt. Rules: after any fix, **`git grep` the pattern across the whole sibling set and list every hit before declaring done**; the set includes documentation mirrors and the summary doc, not just code; and pin it with a check that fails on the original defect (`check-triggers.mjs` is the working example) — a comment saying "❌ don't change this back" has never stopped anyone. *Awareness of a defect class is not immunity to it; only an executable check is.*
- **pushed-is-a-local-belief-not-a-remote-fact** (4 retired projects, 2026-08-27) — ⭐ **`0 unpushed commits` does NOT mean "the code is safe on GitHub" — it means the local cache agrees with itself.** Before deleting four project folders I "verified" each was fully pushed with `git remote -v`, `git rev-list --count @{u}..HEAD`, `git status --porcelain` and `git stash list`, said so in writing, deleted them, and wrote *"the GitHub repo still exists, clone it back"* into MASTER.md, the global CLAUDE.md and two memory files. **Every one of those repos had already been deleted from GitHub.** `@{u}` resolves against `.git/refs/remotes/origin/*` — a snapshot of what the remote looked like the last time a fetch succeeded; a repo deleted server-side leaves that ref untouched, so the count stays 0 forever. Worse, the fetch in my own sync script was written `git fetch --quiet 2>/dev/null`, so the "repository not found" that would have exposed it was swallowed. The truth only surfaced when a `git push` failed on a different project. Rules: **a remote-tracking ref is a RECORD of the remote, not the remote** — to prove a copy exists, hit the server (`git ls-remote origin` / `gh repo view <owner>/<repo>`), and never `2>/dev/null` a fetch whose failure is the thing you need to hear; before any irreversible local delete justified by "it's backed up", **verify the backup at its own source, in the same breath as the delete**; and say what you actually checked, not what you concluded. Kin: [[a-comment-is-not-evidence]] — a tracking ref is the code's comment about itself.
- **python-write-on-windows-turns-a-file-crlf** (trigger scripts, 2026-08-27) — ⭐ **`io.open(path,'w')` in Python on Windows silently translates every `\n` into `\r\n`** — text mode does newline translation by default — so any file you patch with a quick Python one-liner comes back CRLF even though nothing in your code wrote a `\r`. Cost: the `reviver` trigger **could not be launched at all, six attempts in a row**. The Workflow permission handler refused the whole script — *"script contains control characters that would be hidden in the approval dialog"* — and because the error named `script` while the obvious suspect was the long non-ASCII `args`, the search went to emoji, variation selectors, file size and Thai text first. All wrong. The control character was `\r`. The control experiment that settled it: of six scripts, **`lucifer.js` was the only one still LF, and the only one never edited with Python** — a 6-for-6 correlation. Rules: **pass `newline=''`** when Python must write a file (`io.open(p,'w',encoding='utf-8',newline='')`), or use an editor tool that writes LF; **normalise before shipping** (`s.replace(/\r\n/g,'\n')`); and **put a `no CR` check in whatever guard protects the file**, because a stray `\r` is invisible in every diff and every editor. Method note worth keeping: the bug was found with **zero agents** by building throwaway workflow scripts that `return` immediately and bisecting the variables (ASCII passed · Thai + emoji + box-drawing passed · an 87 KB ASCII file passed) — when a trigger will not fire, probe the harness with something that costs nothing rather than re-firing the expensive thing. ⚠ **A trigger that cannot fire is worse than one that fires badly: there is no output to read and nothing to debug from.**
- **severity-is-a-fact-about-the-world-not-about-the-code** (SHIP-MONITORING, 2026-08-27) — ⭐ **you can prove a defect from the repo; you cannot prove its URGENCY from the repo.** I proved by execution that a machine still on `v1.3.4.6` was locked out of both update doors, and shipped it headed *"🔴 ships stranded — both doors shut"*. Every technical sentence held up (the owner confirmed both BLOCKERs and fixed them), but the headline asserted an **active incident** — and there wasn't one: the owner asked Nick, who said there is **one machine and it already crossed the bridge**. The conditional was true; the framing was not, and the receiving session said it *"almost repeated the mistake by taking the frame wholesale."* Severity is a product of the defect **and** the population it lands on — how many units are in the field, on what version, who touches it, what a failure actually costs — and **none of that is in the code**; it lives with the owner. Rules: state the defect and its trigger condition as proven, and write the impact as **conditional until the owner answers** ("IF units remain on ≤X, they are locked out — how many are there?"); **ask before assigning a severity band**, not after; and when you hand a finding to another session, remember they will inherit your frame along with your evidence, so a wrong frame propagates further than a wrong fact. Kin: [[a-comment-is-not-evidence]] — same move, one level up: there I asserted where code lived without opening it, here I asserted what code *was doing to people* without asking them.
- **git-itself-writes-crlf-and-then-reports-the-file-clean** (all repos, 2026-08-28) — ⭐⭐ **`core.autocrlf=true` with no `.gitattributes` makes git write CRLF into the working tree on every checkout — and then report `git status` clean, because it normalises CRLF back to LF when it READS the file.** The corruption sits on disk while git says nothing is wrong. Proven, not assumed: `rm tools/reviver.js && git checkout -- tools/reviver.js` produced **647 CR characters**, and the Workflow permission handler refuses any script containing a CR (*"control characters that would be hidden in the approval dialog"*). **So a fresh clone of any of these repos had CRLF trigger scripts and NOT ONE trigger could fire** — rule #22 (a cloud instance sees only the repo) failing completely and silently. This is the same CR that cost six failed launches the day before from a different cause (Python's `io.open` on Windows), which is the point: *the file content is fine, the line endings are not, and nothing in the normal workflow shows it.* **How it surfaced is worth keeping:** a peer noticed a file marked ` M` by `git status` whose `git diff` was **empty** — a contradiction, not a failure. Chasing "modified but identical" led to the whole thing. **And the guard was blind in exactly its own shape:** `check-triggers.mjs` was the one file its own LF check never covered, so it inspected five green scripts while itself sitting at 472 CRs. Fixes: a scoped `tools/.gitattributes` (`* text eol=lf`) synced to every repo — pinning the scripts without touching the project's own line-ending conventions — and the guard's raw checks now include the guard itself. Rules: **`git status` clean is not "the bytes on disk are what you think"**; when a tool refuses a file for reasons about *characters*, check line endings before anything else; and any check that applies to "every file we ship" must include **the file doing the checking**.
- **a-local-commit-in-a-shared-tree-arrives-with-no-signal** (fleet sync, 2026-08-28) — ⭐ **`git fetch` can only warn about commits that came from the REMOTE. A commit made directly in someone's working tree moves HEAD under their feet and their session-start sync reports nothing at all.** This machine keeps one working tree per project and several Claude sessions work inside them, so a fleet sweep that commits "in the repo" is committing *at somebody's desk*. Five such commits landed in SHIP-MONITORING; its session found them by reading its own `reflog` and seeing `commit:` five times where `pull:` should have been — **rule #21 (fetch-before-work) was in force the whole time and could not have fired once**, because there was nothing on the remote to be behind. Nothing was damaged: the staged scope was `tools/` + `memory/SHARED_LESSONS.md`, no `src/`, and an unrelated `.dart` edit plus 15 uncommitted files in another repo stayed out — *because* the sweep staged explicit paths rather than `git add -A`. But the only reason the owner knew was that they were told in chat, and **chat is not a mechanism**. Rules: before committing in a repo you are not the session for, **check whether its tree is dirty** (someone is mid-task) — the sync script now prints an `OCCUPIED` list; when it is occupied, **hand the commit to the session working there, or announce before and after**; **never `git add` a directory in a repo you do not own**; and remember the general shape — *a safety net that watches one channel is silent about every other channel*, so ask which channel your change actually travels on before trusting the net. Kin: [[a-fleet-sweep-must-ask-each-repo-where-it-is]] — that one asked *which branch*; this one asks *whose desk*.
- **a-fleet-sweep-must-ask-each-repo-where-it-is** (fleet sync, 2026-08-28) — ⭐ **a loop over ten repositories that assumes they are all on `main`, and verifies against `refs/heads/main`, reads "success" while committing somewhere else entirely.** Syncing shared rule files across the fleet, I committed + pushed + "verified" each repo four times over. Nine were on `main`. **AI-Smart-Inventory was on `clean/v1.0.3`** — another live session's working branch — so all four sync commits landed there, `main` never received them, and my check (`local HEAD == ls-remote refs/heads/main`) printed **OK on server** every time, because it compared a ref I had not moved with a ref I was not on. Two independent defects, both of which the same one-line habit hides: (1) `git add -A <paths>` **stages nothing at all** when any one pathspec is missing from that repo, so several commits were silently empty — and `HEAD == remote` is *also* true when nothing was committed, so the verification could not tell a good push from a no-op; (2) a broad `add` in a repo someone else is working in will sweep up their uncommitted work (an unrelated `.dart` edit sat right there). Rules: **read the current branch per repo and verify against `refs/heads/<that branch>`**; assert a **new commit exists** (`before != after`) as well as that it reached the server — sameness alone proves nothing; **stage explicit file paths, never `-A` over directories**, especially in a repo you do not own; and before a fleet sweep, check which repos have a live session (`ListAgents`) — landing commits on someone's feature branch is not yours to clean up afterwards, so **tell them rather than checking out their tree**. Kin: [[pushed-is-a-local-belief-not-a-remote-fact]] — that one asked the wrong *server*; this one asked the wrong *ref*.
- **a-negative-check-passes-vacuously-when-its-subject-is-absent** (trigger scripts, 2026-08-28) — ⭐⭐ **"this sentence must NOT appear" is satisfied by a file that does not exist — so the check reports GREEN precisely when it has checked nothing.** One line did it: `const present = fs.existsSync(p) && re.test(read(p)); present === want ? ok() : fail()`. With `want === false`, a missing file gives `present === false`, and `false === false` passes. **Three checks were silently green in all ten project repos, and two of them were the guards for `#14.7`'s fourth digit** — the rule whose failure made `1.3481` and `1.348` parse to the same tuple and stranded a fleet the day before. The guard against *"the rulebook still permits a fourth digit"* had been reporting clean **because the rulebook was not there to read**. Note what this is not: not a crash, not a red, not a warning — a positive result, indistinguishable from a real pass, on exactly the rule that had already cost the most. **How it was caught matters more than the bug:** nobody hit a failure. A peer noticed the ARITHMETIC didn't close — 13 red became 15 skipped where 12 was the only number that could be right — and went looking for the missing 3. *A number that doesn't add up is evidence, even when everything is green.* Rules: **absence is its own outcome and must be decided before the assertion is evaluated** — missing → skip (only for a named, closed set of legitimately-absent files) or fail, with `want` never consulted; treat every negative/absence assertion as fail-open by default and ask "what does this return when the subject isn't there?"; and **run reconciliation on your own counts** — before/after totals that don't line up are a finding, not a rounding error. Kin: [[a-guard-must-be-tested-with-the-bug-it-guards]] (a guard green for the wrong reason retires the worry), [[a-guard-red-for-an-unfixable-reason-teaches-people-to-ignore-it]] (this one was hiding *underneath* that one).
- **a-guard-red-for-an-unfixable-reason-teaches-people-to-ignore-it** (trigger scripts, 2026-08-28) — ⭐ **red-for-the-wrong-reason costs exactly as much as green-for-the-wrong-reason, and it is easier to miss because it feels like the guard is working.** `check-triggers.mjs` travels into every project repo (#22), but 15 of its 98 checks target files that live only on the master machine — the rulebook, the brief, `tidy.mjs`. In the master directory it read a clean **98/98**, which is the only place I ever ran it. In SHIP-MONITORING the same file read **red 13** — every failure naming a file that repo is not supposed to have, and that nobody working there could fix. The owner of that repo raised it, and their reasoning is the lesson: *a guard that stays red for a cause the reader cannot act on teaches every session to stop looking at it, and the day it goes red for a real reason nobody notices.* Two more defects sat underneath: one "missing" file was actually **present one folder away** (#22 syncs rule docs to `memory/`, scripts to `tools/`, and the guard resolved only against its own directory) — a check reporting ABSENT about a file it simply did not look for; and once the skips were added, the summary printed *"83 passed, 0 failed"* with **no mention that 15 never ran**, which reads as full coverage — the silent scope cut this very guard exists to catch. Rules: **run the guard where it will actually be run**, not only where you wrote it; resolve a target across every location the layout puts it in before declaring it missing; **skip must be a third outcome that is counted and named aloud** ("skipped is *not examined*, never *examined and clean*"), and skipping may only ever apply to a **named, closed set** of legitimately-absent files — a missing trigger script must still fail, or the fix becomes the fail-open bug wearing a new hat. Kin: [[a-guard-must-be-tested-with-the-bug-it-guards]], [[a-degraded-run-must-not-read-as-a-complete-one]].
- **a-summary-of-an-error-is-not-the-error** (trigger scripts, 2026-08-27) — ⭐ **the harness's one-line summary of a failure names the layer that NOTICED, not the layer that failed — read the raw exchange before you fix anything.** Two of three `reviver` firms kept dying with *"StructuredOutput retry cap (5) exceeded — 5 failed calls with no valid output"*. That sentence points straight at the schema, so I slimmed the schema twice: `required` 21 → 8 fields, then `findings[]` 10 → 5. **Neither helped, because neither touched the cause.** The per-agent transcripts (`subagents/workflows/<run>/agent-*.jsonl`, readable with **zero agents**) carried the real message: `InputValidationError: … could not be parsed as JSON. You sent (first 200 of 67609 bytes)` — 67 KB, 55 KB, 57 KB, 68 KB, 36 KB, 48 KB, six attempts, every one **truncated mid-sentence** so the braces never closed. The surviving firm's report was smaller. The failure was **output length**, not schema shape; retrying produced another over-long answer, five times, then the cap fired and the harness summarised it as a schema problem. Rules: when a wrapper reports a failure, **open the underlying request/response before forming a theory** — a retry cap describes the *giving up*, never the *failing*; a fix that changes nothing is evidence the diagnosis is wrong, not that the fix was too small (**two failed rounds should have sent me to the transcript, and did not**); and prefer a constraint the producer can *see and correct* over one it can only violate — binding `maxLength` per field turns "too long" into a schema error the model reads and fixes, whereas an unbounded field lets it write into the void. Kin: [[a-comment-is-not-evidence]] — a summary describing an error is the error's comment about itself.
- **verify-before-delete-or-claiming-fixed** (NotiWallet, ScanDocs, OCR) — don't trust a subagent's "unused/remove" claim, nor a "fixed" status; grep-verify against live code; verify the fix is actually MERGED to main (a Lucifer-worktree fix never merged); confirm the LIVE running version before treating a report as unfixed.
- **test-with-real-corpus** (MyDocs, NotiWallet, OCR) — bugs slip past tests built on idealized synthetic inputs; a permanent-drop gate tested only on clean formats can silently kill the whole pipeline ("all banks silent" ≠ the listener died). Build the corpus from REAL files/formats.
- **green-test≠real-acceptance** (ScanDocs) — for an OpenCV/CV fix a green flutter test means nothing (the cv2≠app trap); acceptance = Python+cv2 on the REAL photo / on-device logcat / Nick's REAL exported file. Don't chase a fully-AUTOMATIC CV result — default to user-confirmed manual corners + a real-photo regression net.
- **silent-op-reads-as-broken** (NotiWallet) — a silent background op (auto-update on quit, no status) reads as broken. Give a visible "ready + Install now" affordance; never silent-install-on-quit as the only path for a tray app.
- **gate-destructive-actions-not-just-creation** (ScanDocs) — a Pro gate on create but not delete lets a lapsed user destroy what they can't recreate. Gate every destructive action.
- **race-generation-counter** (ENA) — an orphaned worker's late callback paints stale data / clears the new flag. A generation counter drops stale-gen callbacks; one consumer per cycle.
- **off-thread-ui-work** (OCR, ENA) — DB/decode/render on the Tk/UI thread hangs. Run off-thread via a controller with debounced refresh; logging belongs in the fetch worker, not card render.
- **exception-before-reschedule-kills-ticker** (HAPPY) — an exception escaping before the reschedule line stops the periodic drain forever. Wrap the handler in `try/except` so the ticker always reschedules.
- **dead-feature-from-namedtuple-arity** (HAPPY) — growing a NamedTuple but unpacking the old arity crashes the page. Attribute access + a field-count regression test.
- **central-resolver-leaves-local-copies** (NotiWallet) — centralizing one lookup leaves drifting local copies. After delegating, grep for local copies (e.g. `Icons.*`) and fix every surface in one change.
- **replace-all-misses-quote-variant** (PLC) — a literal appears single- AND double-quoted; `replace_all` matches one style. Shared helper + grep both quote styles.
- **hang-is-not-a-throw** (ScanDocs) — `catch` handles a throw but not a HANG; spinners spin forever. Add a timeout to every heavy await + wrap busy flags in `try/finally`; surface a clear error.
- **silent-catcherror-hides-failure** (ScanDocs, ScanDocs) — a `catchError`/composite helper that swallows the error makes a failure look like slowness / a silently-missing stamp. Log errors; make composite helpers THROW; resume unfinished work at startup.
