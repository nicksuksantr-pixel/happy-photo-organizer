**Cause (D1, `bug/bug_v1.066.md`):** pystray's tray thread is non-daemon, so `sys.exit(0)` with the tray running hangs in
`threading._shutdown`.
- Old installers hid it with `taskkill /F`.
- v1.066 removed that (U4) and waits instead.
- v1.066's own handover has the same bug.
- Reproduced in a 15-line script on Nick's PC; `icon.stop()` first makes it exit in 3 s.

**Ruled out by measurement:**
- *The disconnected session:* everything above ran while it was disconnected.
- *The route:* the env var reaches the app.

**Proposed fix (waits for Nick):**
1. *The bridge, in the v1.066 installer:* in `--upgrade`, when the process that launched it is the HPO exe from the folder
   being replaced and it is still alive after a short grace, end exactly that PID, then swap. Parent PID, image path and
   creation time are checked; no other process is touched.
2. *v1.066's own exit:* the tray runs on a real daemon thread, and the handover stops the tray and the receiver before
   `sys.exit`.
3. Tests for both, a rebuild, a re-upload to the test repo, and a re-stage.

The harness should also stop at a terminal `FAILED` line and write progress while it waits.
